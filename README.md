# Assignment Agent

基于 undergraduate-assignment skill 的本科作业 Agent：
导入材料 → 自动解析与规划 → 自动检索、取图与逐章写作 → 写后核验与修复 → 最终 Reference 核验 → 自动完成记录 → 导出 DOCX。

## 本地网页工作台

在项目根目录启动：

已有旧数据库时，先按下文“数据库版本与升级”停服检查并迁移，再启动工作台。
新数据库会自动初始化；未知结构或不兼容版本会停止启动。

```powershell
uv sync --locked
uv run assignment-agent-web
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，按 `Ctrl+C` 停止服务。
也可使用 `uv run python -m assignment_agent.web`。
可选参数：`--port 8001`、`--db workspace/other.sqlite`、`--env-file .env.local`。

- 点击右上角“配置模型”，填写自定义 API 地址、模型名和 Key；也可直接使用下文的 `.env` 配置。
- 上传作业要求，按需添加评分标准和课程材料，点击“开始解析”。
- 默认自动推进大纲、章节和全文；材料缺少字数、引用格式或网络图片要求时，先在工作台等待用户回复。回复未说明的项目由模型评估并记录依据。
- “材料与依据”展示来源位置及提取要求；“修改记录”保留各版内容。
- 从左侧任务列表重新打开作业；生成中刷新页面会重新连接当前操作，失败或服务重启后可点击“恢复任务”。
- “运行诊断”展示脱敏校验位置、请求 ID、HTTP 状态、耗时与服务返回的 token 用量。

AI 自动生成章节、论证目标、评分覆盖、证据需求与字数预算，并逐章写作。
章节通过证据检查后自动继续；完成记录绑定正文版本，最终核验通过后可直接导出。
旧版本、旧人工记录和每次自动推进均保留；旧中断在恢复时迁移到自动流程。

全文最终实际使用的独立引用来源最低为 3 个，不要求每章分别达到 3 个。材料明确规定的网络图片下限继续执行；缺失图片要求时，模型评估的数量只是建议，找不到与正文相关且来源可核验的图可跳过。目录按已确认章节顺序生成，不检索文献、不编造页码或引用。前面章节可暂时没有引用，但没有证据支持的外部事实仍不能通过写后核验；最后一个论证章节补足全文来源差额。
正式来源库只在章节核验通过后，提交正文实际引用和插图实际使用的来源。
候选资料单独存入可恢复的临时池，章节通过后清理未采用的条目、全文和图片；
中断时只保留当前取证池，已用来源按正文版本保存不可变快照，重启可继续恢复。
共享缓存和历史版本引用的文件不会被清理；未用图片可在后续需要时从缓存原文重新提取。
旧混合来源表自动迁移，默认网页只显示当前正文版本的正式来源，不展示候选历史。
同一来源重复引用只算一个；原创图、重复图片、占位符和图片链接不计入网络插图。
直接提交结构化要求时，`min_sources`、`min_web_images` 默认分别为 3、2；图片下限可显式设为 0。
缺失要求会保存在 analysis 中并等待用户回复；未回复不会继续调用模型或生成大纲。
大纲生成后，AI 按当前章节的论点、rubric 和证据缺口规划检索词，使用 OpenAlex、Crossref、
Semantic Scholar 获取论文与开放仓储全文，先筛选候选相关性，再按真实论文原图注定位、裁剪图片。
有必须完成的插图下限时，另外检索带 CC BY、CC BY-SA 或 CC0 许可线索的 OpenAlex 候选；
筛选时提供已提取图片、许可和版权检查结果，避免反复选择没有可用图的全文。
索引许可只用于发现图源，不能代替 PDF 原文授权和单图版权核验。
图源使用独立的简短查询；已完整缓存的来源自动保留，不占新增下载的筛选名额。
模型重复返回已知缓存编号时自动移除并记录，未知编号仍拒绝整次筛选，不下载未确认来源。
每次查询、选中新候选及复用缓存的来源编号均写入检索事件。
公开网页检索作为补充入口；搜索摘要不能直接作为引用，须返回原站核对书目信息和全文。
免费网页检索聚合 DuckDuckGo、Bing RSS、匹配主题的 Microsoft Learn，去重后统一筛选；
严格执行 site 域名约束，同时加入不限域查询，并轮换文档站与官方博客域名。
空结果、格式错误或服务失败会切换渠道，202/429/验证码响应冷却五分钟，SQLite 保存冷却及逐渠道事件。
模型可规划查询并提供少量未核验候选网址，程序实际抓取核对后才可使用；候选记录不算联网搜索或有效引用。
不新增搜索 Key，不自动调用供应商收费搜索工具。免费渠道与候选均不足时保留检查点，恢复后继续。
当前支持的官方文档图源为 Microsoft Learn：核对页面指向的 MicrosoftDocs 原文、
对应仓库原图与网页图片一致、仓库 CC BY 4.0 许可，再保存完整声明链。
也支持已核对文章正文实际关联的位图，保存原网页、图注、原图网址与字节哈希；
网页通用许可不自动推定为单图授权。正文中的装饰图标、无法解码的图片及不安全地址会排除。
插入前对实际使用的图片执行本地 OCR，记录原图版权声明，保留图内标记；发现声明冲突时标为待核对。
无需填写关键词、手动寻找文献或逐项批准引用；“来源库”只展示自动收集、使用及核验记录。
检索层独立于用户自定义模型 API，不新增模型供应商或搜索 Key 选项。

正文写作使用受约束的引用和图片标记，绑定来源 ID、逐字证据、PDF 页码、原图号和图意解释。
程序插入作者年份引用或 IEEE/Vancouver 数字引用、图片、图注及实际使用的 References；
图片出处保留原 PDF 网址、页码、原图号及许可链接，Word 导出实际嵌入本地图片文件。
网页原图保存原网页、原图网址、许可原文及校验哈希，不编造 PDF 页码或论文图号。
检索到的候选、重复来源、未插入的图片和占位符不计入正文 3/2 目标。
图片优先分配到大纲明确要求图示的章节，引言不为配额强行插图，结论只复用此前的引用。

写后先校验原文和页码、正文引用位置、插图位置、来源文件哈希及实际引用网址/DOI 对应性，
再由模型独立核对论据支持性、图片与本节关系、图注准确性和许可适用性。
核验针对已插入引用和图片的文章版本，不能仅凭存在 DOI 或相似标题算作完成。
每次写作和重试先复用已核验的来源和图片。前面章节只有图片目标或独立核验发现必答项缺少直接证据时才按缺口检索；最后一个论证章节还会检索全文尚缺的独立来源。每批结果先核对全文和图片，够用即停止后续查询和渠道切换。仍失败则保存原因和断点，可点“恢复任务”。
模型鉴权、网络或连接错误直接交检查点恢复，不自动重复请求。失败稿不会自动成为通过核验的正文。
纯 JSON 结构错误在对应请求内修复一次，记录脱敏字段路径与错误类型。核验漏项时重试核验，沿用当前草稿。
只有逐字引文或页码绑定错误时，先尝试一次只允许 quote/page 字段的局部修复；
模型只选择原来源内的证据段落编号，程序原样复制整段文本及页码，避免重抄 PDF 断词字符或措辞。
正文、论点和来源编号不变；修复后仍须严格匹配原文并通过语义核验。
其他标记与绑定问题在原稿上修正标记和证据记录，改动正文措辞的补丁会被拒绝。恢复时继续修复已保存的草稿。
原稿、通过及被拒绝的修复绑定和原因均保存到 SQLite。
正文来源 ID 被模型缩写时，仅补全证据池内唯一且已经绑定的 ID；保留原稿与补全映射，
未知或有歧义的缩写仍拒绝，补全后继续执行原文与语义核验。
同章同版本重试累计保留核验意见，恢复时读取最近 60 条阶段记录，避免格式错误覆盖此前的事实范围限制；
只有整章通过才清除待修复意见，不混用其他章节、版本或材料的记录。
单章核验只检查该章的证据与目标，完整 References 在最终环节统一核对。

全部章节生成后执行最终 Reference 核验；内容核验失败时自动回到受影响章节复用证据并修订，
保留旧版本、核验意见和自动推进记录。单次运行最终核验修复最多三轮，失败后可恢复。
原始作业只要求设计特征归类时，不额外要求历史谱系证明；无依据的分类和跨对象引文仍会被拦截。
AI 推荐大纲的机制示例可按已核验证据自动调整：先提出修订，再独立对照原始 assignment、rubric
和来源原文审查；硬要求、选型、章节目标、标题顺序、评分覆盖、预算与引用插图下限不变。
修订前后计划、理由、证据和核验结果保存 SQLite，网页历史记录可查看当前执行大纲。
修订因必答项缺证据被拒时，审查意见进入下一轮定向检索。硬约束或绑定错误保留供修复。
原始大纲与来源上下文保留；恢复沿用通过核验的修订，修订后的正文必须重新核验，旧稿不能直接导出。
网页正文检查会排除空页、加载页与验证码，重取一次仍不完整则不进入写作证据库。
LWN 旧文章还核对原页面的专用署名栏与发表日期，不用页脚、评论或修改日期补造书目信息。
证据段落按章节目标、检索词和失败反馈中的缺口排序，避免只给引言泛论而遗漏具体证据。
写作须保留选定对象和实验条件，其他系统或研究原型仅作明确标注的旁证；
缺乏可比实测数据时进行有依据的定性比较，引用前后的推断仍须独立受到原文支持。
证据池只为所需新增来源和不同图片预留必要名额，其余按当前查询主题保留代表性文字证据，
避免单一主题或所有图源占满输入名额。同章最近通过稿的来源线索仍须通过当前完整性筛选，
入池不代表旧论据自动通过。已用来源失效时自动重新下载核对，保留人工排除；
来源快照更新后，引用旧快照的章节须重新写作与核验，不能沿用旧通过记录导出。

按用户选择，图片来源可核验即可；许可不明、适用条件未确认或原图版权声明只记录提示，
不阻断生成、恢复和导出，也不自动标为已获授权。来源库、正文图片出处和 Word 保留对应提示。
图片来源关联、原图完整性、相关性及图注仍必须通过核验，失败时先复用已核对的原件和图源。
扫描论文和复杂版式可能无法自动定位；程序会重查其他论文，不拿整页截图、生成图或无关图凑数。
文本模型依据原图注和论文上下文核对图意，不声称完成像素内容的视觉识别。

来源、图片元数据与检索事件保存在 SQLite 的 `research_*` 表；每次写作、失败原因、
证据绑定及核验结果保存在 `writing_evidence` 表，并与 LangGraph 的正文版本关联。
原 PDF、提取文本和图片按内容哈希保存在数据库旁的 `research-assets/`，请一并备份。
恢复会复用已保存的正确资料；新检索替换活动候选时保留旧库记录，防止失败候选占满名额。
搜索常规每章最多 6 次、每篇最多 24 次。最后一个论证章节为补足全文 3 个独立来源，可继续使用全篇剩余额度，即使该章超过 6 次；全篇 24 次上限不变。文献与图片检索、备用渠道、重定向和失败的搜索请求逐次计入 SQLite，重试和恢复共用原额度。命中缓存时直接复用资料，已知来源的下载与核验另计。额度用尽后仍可用已保存的证据写作与核验；正文最终不足 3 个有效来源时不会通过全文核验，并保存当前断点及原因。
单次最多 60 个候选供模型筛选，优先处理最多 8 个相关来源。
遇到 Semantic Scholar 429 时本轮停止重复请求该服务，保留其他检索渠道。
单份 PDF 最多 20 MB；长文献最多检索前 120 页并记录实际覆盖范围，不声称已读完全文。
下载设有总耗时上限，并避免因 HTTP/HTTPS 重定向重复下载同一 PDF。
许可版本若只在 PDF 超链接中声明，会结合对应页面的授权文字一并核对。
Crossref 未收录的 DOI（HTTP 404）会转查 DataCite，仍核对 DOI、标题和年份；
不会把索引提示、未取得的 PDF 或未经核验的网页图计作可用图片。
写后网址核验另有请求预算。要求或大纲变化会使旧证据失效，同一推荐大纲的批准不会使其失效。
已完成任务如发现插图或来源缓存缺失，会阻止导出，并允许从最终核验恢复及重写。

自动流程不等待答疑或批准；旧答疑记录仍可查看。
通过全文核验后可直接下载 Word，包含正文、已核验插图和 References，不包含模型配置或修改记录。
下载不调用模型；正文或来源缓存变化会阻止沿用旧完成记录。

## 自定义 API 配置（BYOK）

CLI 仅提供用户自定义 OpenAI 兼容 API，通过统一 Model Adapter 调用
`POST <OPENAI_BASE_URL>/chat/completions`。无供应商预设、默认地址或默认模型。
协议参考：[OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

```powershell
uv sync --locked
Copy-Item .env.example .env
```

在本地 `.env` 填写用户自己的配置：

```dotenv
OPENAI_BASE_URL=https://your-service.example/v1
MODEL_NAME=your-model-name
OPENAI_API_KEY=your-api-key
MODEL_TIMEOUT_SECONDS=300
MODEL_MAX_INPUT_CHARS=300000
MODEL_MAX_TOKENS=
```

地址为基础 URL，不包含 `/chat/completions`、凭据或查询参数。
网页会话默认允许最多 300000 个输入字符，可在“配置模型”中调整；此值是本地请求保护上限，模型服务仍可能另有限制。网页会话配置优先于 `.env` 中的对应值。
单次模型请求默认等待 300 秒，网页会话可调整到最多 1800 秒；超时后保留写作检查点，恢复任务会重试当前未通过的步骤。
进程环境变量优先于 `.env`；可用全局选项 `--env-file <路径>` 选择其他文件。
`MODEL_MAX_TOKENS` 留空则不发送该参数，填写前需确认兼容服务支持。
默认发送 `model`、`messages`、`stream=false`，不强制要求服务支持 `response_format`。
要求解析通过 JSON 提示与本地 Pydantic 校验完成，格式或来源定位失败最多修正一次。
HTTP/超时错误不会自动反复调用，修复配置或服务后用 `resume` 重试失败节点。

Key 仅用于运行时请求鉴权，不放进模型提示词、状态 JSON 或 SQLite 检查点。
API 错误不展示响应正文；意外回显的当前 Key 会在输出保存前替换。
`.env` 是本地明文配置且已被 Git 忽略；也可只使用环境变量。
任务保存当前使用的非敏感 API 基础地址及模型名。可以改用另一 OpenAI 兼容模型恢复检查点；通过下一节点后任务记录会更新为新模型，已通过章节和证据核验记录保留。测试假模型不能接管真实模型任务；Key 可轮换。
`status` 不需要 Key；`resume` 如需继续生成或语义核验，需配置任务原模型。
早期假模型任务仍可查看，但不能直接用真实模型继续，请新建任务。

材料提取文本、当前阶段 skill、已确认大纲及相关草稿会发送到用户填写的 API。
输入超过字符限制时拒绝请求，不截断材料；字符上限不能代替供应商的 token 上下文限制。

## 导入作业材料

```powershell
uv run assignment-agent start --assignment examples/assignment.md --rubric examples/rubric.md --run-id materials
```

支持 UTF-8 TXT、Markdown、Word `.docx`、文本型 PDF 和扫描 PDF。
`--rubric` 可重复指定评分表，`--material` 可重复指定课程材料。
保存提取文本、文件 SHA-256 指纹及来源位置：文本行号、PDF 页码或 DOCX XML 段落号。
空材料、加密 PDF、损坏文件、无法识别文字的 PDF 页面和不支持的格式会明确报错。
每文件限制为 20 MiB、200000 字符，PDF 最多 200 页；每任务最多 20 份、总计 500000 字符。
超限直接拒绝，不静默截断。

DOCX 按文档顺序提取正文和表格内文本，并读取页眉、页脚、脚注、尾注及批注。
不依赖本机 Word，不支持旧 `.doc`；不保留 Word 分页与视觉排版，也不识别其中的图片文字。
DOCX 解压内容限制为 40 MiB。

扫描 PDF 使用本地 RapidOCR 中英文模型与 CPU 推理，模型随依赖安装，运行时无需云端 API。
无文本层的页面会 OCR；带图像的页面也会 OCR，以覆盖图文混排，并按整页文本去除重复 OCR 行。
评分标准 PDF 优先使用布局提取，保留表格列关系；若布局提取丢失较多字符则保留普通文本提取。
OCR 单元带有 `method: ocr`、页码、行号及 `confidence` 识别分数。
识别分数不等于正确率；模糊扫描、手写、公式和复杂表格可能有遗漏或识别错误，需要核对原页。
PDF OCR 单页最多渲染 1600 万像素；文本层直接提取的单元标为 `method: text`。

真实模型根据材料和解析阶段 skill 提取题目、部分、字数或页数上限、语言、引用格式、统计口径及其他要求。
要求记录保留来源 ID、位置及逐字摘录；空白差异会对齐并回填原文，数字、标点和正文差异仍会拒绝。
课程材料不应覆盖作业要求。缺项或冲突会保留已提取结果并询问用户；未回复时不生成大纲。
用户回复未给出具体要求时，模型评估内部写作预算、引用格式和图片目标并记录理由；已有页数上限保持原值。
内部假模型用于离线测试，CLI 不提供假模型选项。
可在工作台回答澄清问题，或通过 start --spec 使用完整结构化要求创建新任务。
页数上限会作为独立要求保存；当前导出尚未核验最终 DOCX 的实际页数。

## Skill 阶段加载

项目的 `skills/undergraduate-assignment/` 是用户现有 skill 的副本。
可通过 `start --skill-root <目录>` 指定其他 undergraduate-assignment 副本。
任务启动时将 Markdown 文档保存为内容寻址快照（数据库旁的 `skill-snapshots/`），
记录逐文件哈希。源 skill 后续变动不会影响当前任务，恢复时需保留 SQLite 和快照目录。

每次模型调用显式接收当前阶段的 `context`，而不是把所有模块拼进提示词：

| 阶段 | 基础入口之外的模块 |
|---|---|
| 解析 | brainstorming-research |
| 大纲 | paper-orchestration |
| 当前部分 | writing-chapters、writing-core |
| 附带课程材料的当前部分 | 额外加载 evidence-driven-writing、literature-review |
| 收尾 | peer-review、verification |

所有阶段包含 SKILL.md 和 using-research-writing 入口；收尾目前仅准备规则上下文，
尚未实现质量检查器。已加载的规则文本保存在检查点；未来阶段首次加载时校验快照哈希。
副本中的可选脚本不会自动执行，也不会递归读取 Markdown 链接指向的所有内容。
模型接口变为 `extract(state, context)`、`outline(state, context)`、`section(state, context)`。
每次调用只发送当前阶段显式上下文；已加载的其他阶段规则不会整包发送。

## 数据库版本与升级

数据库业务表版本与任务状态版本分别管理，当前均为 1。
以下维护命令不需要 API Key，不调用模型。升级前停止所有使用该数据库的服务和 CLI：

```powershell
uv --cache-dir .uv-cache run --locked assignment-agent --db workspace/agent.sqlite db status
uv --cache-dir .uv-cache run --locked assignment-agent --db workspace/agent.sqlite db plan
uv --cache-dir .uv-cache run --locked assignment-agent --db workspace/agent.sqlite db migrate --offline
```

`status` 用于只读诊断；`plan` 在不兼容时返回非零退出码。
`migrate` 为已有旧库自动生成数据库和文件备份，再逐步迁移；当前库重复执行不重复升级。
默认备份在数据库同级的 `backups/<运行编号>/`，维护报告在 `migration-reports/`。
`--offline` 表示已停止业务访问；本版本还会用维护锁拒绝正在运行的操作。

手动备份和恢复到独立新目录：

```powershell
uv --cache-dir .uv-cache run --locked assignment-agent --db workspace/agent.sqlite db backup workspace/backups/manual-f02 --offline
uv --cache-dir .uv-cache run --locked assignment-agent db restore workspace/backups/manual-f02 workspace/recovered-f02
uv --cache-dir .uv-cache run --locked assignment-agent --db workspace/recovered-f02/agent.sqlite db status
```

备份及恢复目标必须不存在。恢复会核对哈希，并生成任务文件路径映射；
历史检查点保留原字节。恢复目录应保持原位置，换目标目录时重新执行 `restore`。
旧备份恢复后如仍显示待迁移，先对该恢复副本执行 `db plan` 和 `db migrate --offline`。
详见[支持范围、失败恢复与迁移编写规则](docs/data-migrations.md)。

## 当前能力边界

- 仅支持本地单用户串行操作，同一数据库不要同时启动多个写入命令。
- 已接入真实 API 适配器；不同兼容服务的参数支持及生成质量需要用户实际验证。
- 已接入证据复用、按缺口检索、实际引用与插图、局部修复和最终 Reference 核验。
- 语义核验依赖所配模型的判断能力，不等于事实绝对正确或自动 rubric 评分；文本模型没有图片视觉理解。
- `word_limit` 目前只校验为正整数并持久化；尚无程序化正文计数或 rubric 评分。
- 自动流程的 `completed` 表示章节生成及最终核验完成，完成记录由程序自动保存，不代表作业已经提交。
- SQLite 保存草稿、历史、章节和全文确认记录及检查点；支持 DOCX 导出，尚无通用 schema 迁移功能。

## 代码结构

- `schemas.py`：任务要求、草稿版本、确认记录和运行状态。
- `graph.py`：可恢复的自动阶段推进及最终核验。
- `service.py`：SQLite 生命周期、任务恢复及确认校验。
- `delivery.py`、`export_docx.py`：全文确认、正文版本校验及 Word 文档导出。
- `advisor.py`：持久保存答疑记录，独立处理失败与重启中断。
- `research*.py`、`public_fetch.py`、`paper_figures.py`：公开检索、下载、论文取图与可恢复来源库。
- `evidence_types.py`、`grounded_writing.py`：引用与插图绑定、自动写作、规则与模型核验、有限重试和最终修复。
- `model_adapter.py`：统一模型接口、BYOK 配置和自定义兼容 API 适配器。
- `fake_model.py`：仅供离线测试的确定性假模型。
- `materials.py`：文本与 PDF 解析、来源定位及错误处理。
- `docx_reader.py`：Word DOCX 正文、表格与附属文本读取。
- `ocr.py`：扫描 PDF 页面渲染、本地 OCR 和识别分数记录。
- `skills.py`：文档快照、阶段模块选择与内容指纹校验。
- `cli.py`：命令行入口，也支持 `uv run python -m assignment_agent`。
- `web.py`、`static/`：本地网页接口、后台任务和响应式工作台。
- `tests/`：模型校验、流程集成及独立进程恢复测试。

提交 `pyproject.toml` 与 `uv.lock`；使用 `uv add` / `uv add --dev` 管理依赖。
`.env.example` 为模型配置模板；程序读取 `.env` 或 `--env-file` 指定文件。
`.env`、`.venv`、`workspace/` 已忽略；不要提交密钥或真实作业材料。
