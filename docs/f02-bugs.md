### F02-B007：正式来源文件未纳入备份前的引用完整性校验

位置：[backup.py](../src/assignment_agent/migrations/backup.py) 的 _backup（第 62～83 行）。
实现扫描现有 research-assets 文件，并验证材料和 Skill 清单；未对数据库中正式来源、
历史来源快照等引用的文件逐项核对存在性和原记录哈希。

复现：在临时库登记一个实际存在且通过 asset_valid 的正式来源，再分别删除或改写其 PDF，
移除版本记录模拟旧库，执行 migrate。两种情况均报告 completed、数据库版本 1；
缺失场景备份文件数 0，改写场景备份文件数 1，但正式来源完整性均为 false。
这不能证明原本缺失的数据可恢复，也不能将现有文件的新哈希当成原引用哈希通过验证。

验收缺口：引用文件缺失或哈希不符应明确阻止完整备份和后续迁移；
不能只验证已经扫描到的文件在复制过程中是否变化。

### F02-B008：备份清单缺少完整性和路径映射结构校验

位置：[backup.py](../src/assignment_agent/migrations/backup.py) 的 verify/restore（第 154～208 行）。
verify 逐项检查已有 files 条目，未与备份数据库的必需文件引用交叉核对，
也未在写入恢复目录前验证 roots 的结构与映射覆盖范围。

复现 1：生成含材料引用的有效备份，将 manifest.files 改为 []。
verify 与 restore 均成功，恢复库显示 current，但映射后的必需材料文件不存在。
复现 2：将 roots 改为 null。verify 仍成功；restore 创建目标并复制数据库后抛 TypeError。

验收缺口：不完整或格式错误的清单应在开始恢复前被拒绝；
恢复成功必须包含数据库引用所需文件及可用的路径映射。

### F02-B009：内部对象名称过滤范围过宽

位置：[inspection.py](../src/assignment_agent/migrations/inspection.py) 第 44 行。
模式 name NOT LIKE 'sqlite_%' 中的 _ 是单字符通配符，过滤了不属于 sqlite_ 内部命名空间的普通对象。

复现：对临时当前库创建普通表 sqliteX_foreign(id TEXT)，inspect 仍返回 current，
返回的 tables 中也没有该表。验收要求未知非内部对象必须报告并停止。

### F02-B010：只验证已有索引，没有检查必要索引缺失

位置：[inspection.py](../src/assignment_agent/migrations/inspection.py) 第 107～119、151～153 行。
验证遍历实际存在的索引；当前版本的必要结构检查只覆盖表，未要求目标版本索引存在。

复现：当前库执行 DROP INDEX research_search_attempts_run_chapter，
inspect 仍为 current，migrate 返回 current/applied=[]。
本问题尚未观察到数据丢失，但结构识别结果不完整，不符合目标版本表和索引一致性验收。

### F02-B011：非字典 run 状态被静默跳过

位置：[backup.py](../src/assignment_agent/migrations/backup.py) 的 run_values（第 33～47 行），
影响 [runtime.py](../src/assignment_agent/migrations/runtime.py) 第 34～36 行及 Web 启动保护。
读取器只 yield 字典，没有区分 run 不存在与 run 已存在但类型损坏；
因此后续 RunState 校验根本没有收到损坏值。

复现：分别将检查点 channel_values.run、writes 中 channel=run 的值改为字符串。
两种情况下 inspect 都显示 current，Web 启动成功，启动清理把答疑 pending 改为 failed，
主数据库哈希发生变化。验收要求损坏状态在任何启动清理前被拒绝。

建议修复顺序：B011 → B007 → B008 → B009 → B010；每项新增回归并单独验证。
