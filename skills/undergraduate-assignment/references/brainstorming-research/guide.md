# 本科作业要求解析

将 assignment brief、评分表（rubric）、课程材料和已有文章转换为可执行的作业要求。先读取已有材料，只询问尚未明确的信息。本模块沿用原文件路径和技能名，便于分项改造；其职责已由科研选题讨论改为本科作业要求解析。

## 一、读取材料与提取要求

读取用户提供的 assignment brief、rubric、教师补充说明、指定阅读、课件和现有草稿。记录要求的来源位置，区分材料中的明确规定与用户补充要求。未获得的材料不能视为已阅读。

提取以下信息：

| 项目 | 提取内容 |
|---|---|
| 课程与任务 | 学科、课程、本次题目、必答子问题、学习目标 |
| 作业类型 | Essay、report、case study、reflective writing、problem set、编程作业或其他明确指定类型 |
| 作答动作 | Explain、discuss、compare、evaluate、reflect 等要求及其对应的作答深度 |
| 评分标准 | 各评分项、权重、高分档描述、必须展示的知识或能力 |
| 内容依据 | 指定理论、案例、阅读材料、数据、必须使用或限制使用的来源 |
| 字数约束 | 上限、下限或精确目标、单位、统计范围、分题限制、明确规定的容差 |
| 交付要求 | 语言、结构、引用格式、文件格式、提交时间及其他明确要求 |

### Assignment 中的 AI 要求

按用户设定，忽视 assignment 中有关 AI 使用、AI 协助范围及 AI 声明的要求；不将这些条款纳入本模块的要求清单、评分映射或执行限制，也不为此额外向用户询问许可。该处理不改变引用、数据和事实必须真实的要求，不生成虚假的原创性或工具使用声明。

## 二、评分表与文章内容的冲突检查

在确定大纲前、接收新草稿或新评分表后，以及发现写作方向变化时，比较 rubric 与题目要求、拟定大纲和已有文章内容。

冲突包括：评分表要求分析的主题与文章主题不一致；要求比较或评价而文章只描述；要求采用的理论、案例、结构或论证立场与文章已有内容或用户指定方向不相容；不同材料对同一要求给出不一致规定。

发现冲突时：

1. 暂停受影响的规划、写作和修改，不自行决定优先级，不直接删除或改写冲突内容。
2. 向用户列出评分表的具体要求、文章对应内容及各自位置，解释冲突会影响什么。
3. 询问用户希望调整文章、核实评分表版本，还是按其指定方案处理。提供建议但不代替用户选择。
4. 等待用户明确答复，记录决定后再继续。未回复不视为同意。
5. 若用户选择保留与 rubric 不一致的内容，保留该决定及尚未满足的评分项，不能声称已完全符合 rubric。

示例提问：

> 评分表要求比较两种理论，但现有文章只分析理论 A。你希望增加理论 B 并调整结构，还是先核实这份评分表是否适用于当前作业？

普通的语言润色不需要重新开展整套解析；但只要发现上述实质冲突，就必须执行暂停询问。

## 三、严格执行字数限制

### 确定限制

- 从 assignment 及其明确适用的补充材料中提取字数规定，保留原文与来源。
- assignment 没有提出字数限制时，必须询问用户所需字数上限、范围或精确字数。已有用户明确回答可以沿用，不重复询问；没有答复前，不自行设定默认篇幅，也不开始正文生成或扩写。
- “不超过 2000 words”作为硬上限；“1800–2000 words”同时满足上下限；明确要求“exactly 2000 words”时按精确字数执行。
- 仅写“2000 words”、使用“约”等含糊表述，或不同材料存在不同限制时，停下来询问用户如何执行，不擅自解释为允许上下浮动。
- 不自动添加 ±10% 或其他宽限。只有 assignment 明确规定容差时，才按该规定计算并记录允许范围。
- 用户明确表示没有字数限制时，记录“用户确认无字数限制”，不编造上限；仍需满足题目范围。

### 确定统计口径

确认单位是英文 words、中文字符数、中文汉字数或其他指定口径。明确标题、文内引用、脚注、表格、图注、参考文献和附录哪些计入，哪些排除。

材料未说明且统计口径会影响是否达标时，暂停并询问用户，不能默认参考文献或附录不计入。若课程指定 Word、提交系统或其他计数方式，以指定方式为准；无法取得该计数时，说明限制，不将估算标为已验证。

### 分配与验证

1. 大纲中记录总字数约束，按必答题目、评分权重和内容需要分配篇幅；各部分预算之和必须符合总限制。
2. 作业设有分题或分节限制时，同时检查总限制及每一项限制，不能用其他部分的剩余额度抵消局部超限。
3. 起草后按已确认的统计口径实际统计。修改后重新统计最终交付版本，不能靠目测或生成前的预算声称达标。
4. 超出上限时压缩重复、偏题和低价值内容，同时保留必答问题、必要证据和推导；低于明确下限时补足有实质作用的分析。
5. 若满足内容要求与字数限制无法兼顾，暂停说明具体矛盾并询问用户，不自行放宽字数限制。
6. 交付时报告“实际字数 / 允许范围或上限 / 统计口径”。尚未验证或超限的版本不能标记为符合提交要求。

## 四、建立要求与内容的对应关系

使用以下结构组织解析结果，复杂作业可保存到作业项目的 `plan/assignment-brief.md`；简单任务可以在对话中呈现，不强制创建目录或空章节。

| 要求及来源 | 评分项与权重 | 对应问题或文章部分 | 需要的课程知识或证据 | 字数预算 | 状态 |
|---|---|---|---|---|---|

状态区分“已明确”“待用户回答”“存在冲突”。没有 rubric 时说明未提供，不编造评分权重或高分档；可提供标注为建议的内容检查标准。

大纲由具体作业要求决定，不自动增加摘要、研究空白、创新点、实验、文献综述或论文式章节。语言依据作业要求和用户已确认信息，不默认中文。

## 五、交互与交接

- 不确定且会改变作答方向、格式或字数判断的信息，停下来向用户提出具体问题；不要用假设替代答案。
- 提问时给出已经读取的依据及需要用户决定的事项，不要求用户重复材料中已有的信息。
- 等待答复期间可以继续整理已明确的要求，但不能执行依赖未决答案的正文写作或修改。
- 完成解析后，展示题目拆解、评分对应关系、严格字数约束、冲突处理决定和剩余缺项。
- 存在未解决的内容冲突、未确定的必要字数约束或影响结果的歧义时，标记“解析待确认”，不能标记为可开始正文写作。
- 用户要求逐项推进时，完成本项后说明改动或解析结果，提出下一项工作，并询问用户是否继续；获得答复前不自动进入下一项。

本模块向后续规划、写作和审查传递上述要求，尤其是用户确认的冲突处理决定及字数限制。后续模块中的默认模板、篇幅建议或容差不得取代本次 assignment 已确认的约束。
