# 本科作业结构示例

这些结构仅用于在作业要求允许时讨论大纲，不是默认章节。先解析 assignment brief、rubric、课程材料和已有草稿；以其中明确的题目、必答问题、评分项、格式和字数限制为准。缺少字数限制时先询问用户，不能采用示例篇幅。大纲必须在写作前由用户确认。

## 论证型 Essay

可考虑“引入问题—围绕必答问题展开分析—形成结论”。主体按论点、比较维度或题目子问题组织；是否设置小标题、摘要和参考文献由作业要求决定。需要文献支持的论点应先核查文献真实存在及其是否支持该论点；所有引用文献遵守 DOI 验证规则。

## Report

可考虑“任务或问题—资料与分析—发现—建议或结论”。是否需要 executive summary、方法、图表、附录及其顺序，以 assignment 和 rubric 为准。没有实际研究或数据时，不添加研究方法和结果章节。

## Case Study

可考虑“案例背景—需要回答的问题—证据和理论分析—可行结论”。案例事实、课程概念和评价标准应分别标明依据；不把示例案例写成真实资料。

## Reflective Writing

可考虑“具体经历或材料—分析与反思—学习收获和后续行动”。人称、反思模型和引用要求由课程决定；不得编造个人经历。

## Problem Set 或编程作业

按题号或交付物组织，逐题回应操作要求。展示推导、代码、运行结果或解释的范围，以题目和评分表为准；不强加 Essay 结构。

## 使用规则

1. 先建立作业要求与评分项的对应关系，再选取或改造适合的结构；不要根据“论文类型”自动套用大纲。
2. 如 rubric 与现有文章内容冲突，暂停受影响工作，列出冲突并询问用户。
3. 将确认的字数上限、下限、统计口径和分题限制写入大纲，按要求分配各部分篇幅；不使用任何默认字数或容差。
4. 展示拟定大纲，获得用户确认后才开始正文。每完成一个已确认的部分，展示给用户并等待确认后再进入下一部分。
5. 复杂作业可将最终大纲记录到 `plan/outline.md`；简单作业可直接在对话中记录。
