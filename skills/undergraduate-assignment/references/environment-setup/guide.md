# 本科作业环境配置

仅在作业需要运行代码、生成图表或分析数据，且现有环境不满足要求时使用本模块。先确认 assignment 指定的软件、版本和提交形式，并优先复用已可用的环境。不要因为任务提到“画图”就自动安装 Miniconda、初始化 shell 或创建固定名称的环境。

## 一、确认实际需求

1. 查看 assignment、课程材料及用户提供的代码，列出真正需要运行的程序和依赖。
2. 确认用户指定的操作系统、Python 版本、环境管理方式和已有项目配置；未指定的项目不擅自设为固定版本。
3. 先检查当前环境能否完成任务。环境已可用时直接继续，无需安装或升级。
4. 若任务只需要阅读、讨论或规划，不执行环境配置。
5. 需要安装新工具或改变现有环境且适用范围不明确时，先说明拟修改的环境与所需依赖，向用户确认范围。

## 二、最小检查

在实际运行代码的终端中检查解释器、包管理器及所需库。按当前系统使用相应命令，不跨系统混用。

```text
python --version
python -m pip --version
```

若系统使用 `python3`、`py`、Conda、虚拟环境或课程提供的运行平台，使用对应入口。仅导入任务所需的库，例如绘图任务可检查 `matplotlib`；统计任务则检查实际使用的统计库。检查脚本执行的解释器必须与最终运行脚本的解释器一致。

## 三、缺依赖时的处理

- 优先遵循 assignment 或现有项目的 `requirements.txt`、`pyproject.toml`、Conda 配置及课程提供的环境说明。
- 仅安装当前任务缺少且确实需要的依赖，不批量安装绘图、机器学习和 Notebook 套件。
- 优先在已确认的项目环境或隔离环境中安装，避免无关项目受到影响。用户明确要求使用 Miniconda、Conda 或特定版本时，按其要求配置。
- 不默认升级 `pip`、修改全局包源、初始化 shell、注册 Jupyter kernel 或覆盖已有环境。这些操作只在确有必要且适用范围明确时执行。
- 安装失败先读取实际错误，核对解释器路径、依赖版本与网络条件，再作针对性修复；不自动重装整套环境。
- 课程环境限制安装时，报告缺少的能力和可行的课程允许方案，不假设本地安装能解决提交问题。

## 四、运行与验证

完成必要配置后，用同一解释器重新导入所需库，并运行与当前作业相关的最小代码或脚本。图表任务还应检查输出目录是否可写、生成的文件能否打开，并遵循 `figures-python` 中由 assignment 决定的格式、尺寸和路径要求。统计任务应核对代码实际使用的包与版本。

只报告已经验证的结果；若无法运行，记录具体错误及受影响的交付物，不把“已安装”当成“程序可用”。

## 五、记录

复杂或需要复现的作业可在现有项目记录中注明解释器、必要依赖、运行命令和生成文件位置。没有项目记录时，不强制创建 `plan/progress.md`。环境名称、目录和文件路径由课程要求、用户选择或现有项目决定。
