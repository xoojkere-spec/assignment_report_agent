# 本科作业流程控制

按照已确认的要求管理作业进度：写作前确认大纲，每部分写完后等待用户确认，再进入下一部分。保留原文件路径与技能名，职责已改为本科 assignment 的流程管理。

## 输入与工作边界

沿用[入口规则](../using-research-writing/guide.md)与[作业要求解析](../brainstorming-research/guide.md)的结果：题目、rubric、课程材料、交付要求、严格字数约束、冲突处理决定及用户已确认的信息。

不重复询问已明确的信息。缺少会影响结果的信息时暂停相关工作并询问用户。题目与大纲决定结构，不默认要求研究创新、科研章节、最低章节长度或完整实验系列。普通作业不强制代理分工、任务包或能力使用审计。

## 一、阶段与状态转换

| 阶段 | 本阶段工作 | 进入下一阶段的条件 |
|---|---|---|
| 要求待明确 | 解析要求，处理材料歧义、评分冲突和缺失字数限制 | 影响写作的必要问题已解决 |
| 大纲待确认 | 展示部分划分、顺序、主要论点、评分项对应关系、证据需求和字数预算 | 用户明确确认大纲 |
| 当前部分写作 | 仅撰写当前部分，执行要求与内容两轮检查 | 内容可审阅，相关核实问题已处理 |
| 当前部分待确认 | 展示内容或文件、实际字数、检查结果，询问是否确认并继续 | 用户明确确认后进入下一部分；最后一部分确认后进入全文检查 |
| 当前部分修改 | 根据用户反馈修改，重查受影响的论证、论据和字数 | 返回当前部分待确认，不直接跳到下一部分 |
| 全文检查 | 检查要求覆盖、逻辑一致、引用、论据、总字数和交付格式 | 检查通过，实质内容变更已重新获得确认 |
| 最终交付 | 提供最终文件、实际字数、核实范围及剩余限制 | 仅对有验证依据的事项声称完成 |

“部分”可为 essay 小节、report 板块或一道题，其边界随大纲确认。不按论文习惯自行拆章。

已经批准的大纲无需逐部分重复进行写前确认。未收到当前部分的明确确认，不起草下一部分，也不能先写完整篇后分批展示。最后一部分同样需要确认。用户仅提出修改意见、提出问题或未回复，都不等于确认。

## 二、最小进度记录

在已有项目记录或对话中维护以下内容；跨多轮作业需要持久保存时，可使用 `plan/outline.md` 和 `plan/progress.md`，不要求预建空章节或额外审计文件。

- 当前采用的要求与材料版本，以及大纲确认记录。
- 总字数限制、分题硬限制、单位与统计范围。
- 当前部分、各部分的确认状态及用户的具体修改决定。
- 待解决的冲突、未核实的论据及下一步动作。

| 部分 | 对应题目或评分项 | 预算 | 实际字数 | 当前版本与位置 | 状态 | 确认依据 |
|---|---|---|---|---|---|---|

状态区分未开始、写作中、待确认、修改中、已确认。确认依据记录用户实际答复和所确认的版本，不编造时间或批准记录。未计数字段写“未统计”，不能用预算充当实际字数。

恢复任务时先读取记录，找到最后确认的版本及待处理事项。不能因对话切换或工具执行成功就重置或推进确认状态。

## 三、字数预算与实际计数

严格执行解析模块确认的限制。assignment 未提供限制且用户尚未补充时先询问；没有答案前不自行选择篇幅。用户明确确认无字数限制的情况，按该记录执行。

- 大纲中为各部分分配预算，考虑评分权重、必答内容和分析难度；预算总和必须符合整体限制。
- 区分规划预算与 assignment 的硬限制：部分预算用于管理篇幅，分题硬限制必须逐项满足；不得用其他题目的剩余额度抵消局部超限。
- 每部分写完及修改后，按确认口径实际计数，记录已写总量和可用余额，检查剩余额度是否足以完成剩余必答内容。
- 不默认使用 ±10% 容差。上限、下限、精确字数及明确规定的容差，分别按其原意执行。
- 需要实质改变已确认的篇幅分配或结构时，先说明影响并请用户确认。
- 最终整合后重新统计完整交付版本，按确认口径计入标题、引用、图表或其他内容，不能只相加早期草稿计数。
- 无法兼顾必要内容与限制，或无法取得指定统计方式的结果时，暂停说明并询问。估算不能标记为字数验证通过。

## 四、每部分的两轮检查

### 第一轮：要求检查

检查是否回答本部分题目，是否覆盖对应 rubric 要求，是否使用指定课程知识，是否符合已确认的结构、语言、引用格式及字数限制。

发现评分表与文章内容冲突时，列出两方原文或具体位置，暂停相关修改并询问用户；不能自行决定优先级。用户选择保留不一致内容时，记录该决定及未满足的评分项。

### 第二轮：内容与论据检查

检查概念、计算和推理是否准确，分析是否充分，论点与证据是否对应，段落衔接是否清楚。论据核实必须分为“来源存在”与“内容支持”两个独立判断，不能以引用格式正确代替核实。

#### 1. 核实论据是否真实存在

| 论据类型 | 核实方式 |
|---|---|
| 学术文献 | 查看实际检索到的出版方页面、可靠书目数据库或原文；核对题名、作者、年份、出处以及 DOI（如有）是否对应 |
| 图书、教材、指定阅读与课件 | 查看用户提供的文件或可访问的原始资料；核对标题、版本、章节或页码。文件存在不等于其中每项陈述均已获外部验证 |
| 数据和统计数字 | 找到原始数据、官方统计表或可复核的分析输出；核对时间、对象、单位、分母、样本口径及数值 |
| 事件、案例和法律材料 | 找到原始报告、判决、官方文件或可靠记录；核对主体、时间、事实及适用背景 |
| 直接引语 | 在实际读取的原文中定位引语及上下文，核对措辞和页码或其他可定位位置 |
| 用户经历或观察 | 标记为用户陈述，确认内容来自用户；不虚构经历，也不声称已经独立验证 |

只看到搜索摘要、引用列表或一个形式合理的 DOI，不足以把整条论据标为已核实。DOI 能打开时仍要核对信息是否匹配；没有 DOI 也不代表来源不存在。但按用户设定，所有引用文献仍必须通过 DOI 验证；无 DOI、无法验证或元数据不匹配的文献不能标为通过。必用材料与此要求冲突时暂停询问用户，不自动豁免。不能编造文献、数据、案例、页码或引语。

#### 2. 核实来源是否支持该论点

读取与论点相关的原文段落、表格、摘要或数据记录，记录实际读取范围。仅获取摘要时，只能支持摘要确实包含的信息，不能声称读过全文或据此补出方法、数值和细节。

核对证据的对象、条件和结论边界，防止扩大结论、误用统计数字或把相关关系写成因果关系。间接转引需明确说明，不把二手转述标为直接查阅原文。

用户自己的分析、计算或推导应明确区分于外部事实；检查推理和输入依据，不为其捏造外部出处。示例或模拟数据必须标明性质，不充当真实研究结果。

#### 3. 保留可追溯的核实记录

在现有资料表或进度记录中按需要保存：

| 论点及正文位置 | 论据或来源 | 来源存在状态 | 支持关系状态 | 实际查阅位置或链接 | 问题与处理 |
|---|---|---|---|---|---|

来源存在状态区分“已核实”“仅有线索”“无法核实”；支持关系区分“直接支持”“间接或有限支持”“不支持”“尚未检查”。用户陈述另行标注，不混同于独立验证。

无法访问、未检索到、资料矛盾或支持不足时，标明具体缺口，暂停依赖该论据的内容并询问用户是否补充资料、使用可核实的替代来源，或调整论点。不得将“未找到”直接断定为“不存在”，也不能将用户认可视为来源真实性的证明。

未经核实或不支持论点的材料，不能当作已证实事实进入最终提交版本。用户决定保留待核实内容时，只能明确标为待核实草稿，不能宣称论据审查通过。

## 五、变更与全文检查

新增或更换题目、评分表、材料或大纲后，先检查影响范围。已确认部分若受到实质影响，标记为待修改或待重新确认；保留未受影响部分的确认状态。

所有部分确认后，执行全文检查：

- 题目、必答子问题和评分项是否覆盖，用户选择保留的差异是否明确记录。
- 核心概念、论点、例子及结论是否一致，有无重复、矛盾或遗漏。
- 文内引用与参考文献是否对应，来源存在和支持关系是否均已检查。
- 最终修改是否引入新的事实、数值或引用；新增内容须重新核实。
- 总字数、分题限制、格式和交付文件是否满足确认要求。

检查导致主要论点、论据或结构发生变化时，展示受影响部分并再次请用户确认。交付说明应区分已核实、有限核实和未解决事项，不承诺成绩，不把文件生成成功等同于作业已符合全部要求。

## 六、与其他模块配合

当前部分的撰写使用[部分写作](../writing-chapters/guide.md)；资料整理和论证使用[证据驱动写作](../evidence-driven-writing/guide.md)与[文献处理](../literature-review/guide.md)；按需要使用[审查](../peer-review/guide.md)与[验证](../verification/guide.md)。只读取当前任务所需模块。

上述模块尚有科研规则时，本科作业的流程按本模块、入口和作业要求解析中的已确认约定执行。不要因旧模块要求而恢复固定科研章节、代理分工、额外字数容差或大量审计文件。核实操作使用实际可用的工具，不能声称已执行不存在的脚本或未发生的检索。
