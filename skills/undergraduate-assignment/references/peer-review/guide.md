# 本科作业审查与自查

检查当前部分或全文是否满足已确认的作业要求，发现证据、推理、表达和交付问题。保留逻辑审查、偏倚识别及建设性反馈，不使用期刊接收、拒稿或科研创新突破作为默认评价标准。

## 一、审查范围与输入

读取 assignment brief、rubric、已确认大纲、当前待审版本、字数口径、已有论据核实记录与用户确认决定。明确当前是在审查某一部分，还是全部部分确认后的整篇作业。

沿用[入口规则](../using-research-writing/guide.md)与[流程控制](../paper-orchestration/guide.md)。缺少必要资料时说明未能检查的范围，不假称符合尚未读取的评分表；存在会改变审查结论的不确定性时暂停询问。

不重复要求用户提供已有材料，不自动扩展到题目之外。审查本身不授权修改全文；用户请求修订时按其已授权范围执行。

## 二、初步评估

用两三句话说明题目要求、当前作答的主要观点及整体完成情况。检查：

- 是否准确理解题目动作及所有必答子问题。
- 是否回应 rubric 的各项要求，课程概念是否使用准确。
- 是否遵循已确认的大纲及用户决定，当前版本对应哪些确认记录。
- 是否存在偏题、核心论据缺失、明显推理错误或未满足的硬性限制。

不承诺实际成绩。没有教师明确给出的评分权重或档位时，不自行补造；可提出标明为建议的检查标准。

## 三、按已确认大纲逐部分审查

按当前作业的实际部分及评分项检查，不要求添加摘要、方法、结果或讨论等科研章节。

| 审查维度 | 检查内容 |
|---|---|
| 回答题目 | 是否答全问题，是否达到 explain、compare、evaluate、reflect 等动作所需深度 |
| 课程知识 | 概念、理论和术语是否准确，是否具体应用到题目或案例 |
| 论证逻辑 | 观点、依据、解释和结论之间是否连贯，有无推导跳跃或自相矛盾 |
| 分析深度 | 是否超出资料复述，是否解释证据意义、比较条件或权衡局限 |
| 事实与论据 | 来源是否真实、DOI 是否验证、证据是否支持对应论点，是否夸大结论 |
| 一致性 | 前后立场、术语、数字、单位及引用是否一致，结论是否回应正文 |
| 语言与排版 | 是否遵守保留的写作风格、禁用表达、段落和格式要求 |
| 字数与交付 | 是否按确认口径实际计数，是否满足总限制、分题限制及文件要求 |

反思作业核对经历是否由用户提供，不虚构经历或感受；分题解答核对步骤、单位、计算和答案；编程作业核对题目约束、实际实现及适当验证结果。不要把未执行的检查写成通过。

## 四、论据真实性、DOI 与支持关系

按[文献处理](../literature-review/guide.md)与[证据驱动写作](../evidence-driven-writing/guide.md)检查，并将三个判断分别记录：

1. 来源是否真实存在，作者、标题、年份、版本和出处是否匹配。
2. 所有引用文献是否通过 DOI 验证，实际 DOI 记录是否对应所引文献。
3. 实际读取的内容是否支持正文中的具体论点，且对象、条件、时间和结论范围一致。

DOI 可打开不代表信息匹配，也不证明论点得到支持。只读到摘要时不能声称查阅全文；直接引语需核对原文、上下文和定位信息。文内引用须与参考文献对应，格式按作业规定检查。

数据核对来源、单位、分母、时间和计算口径；案例核对实际记录；用户陈述与独立验证的事实区分。模拟或教学示例不充当真实证据。自己的分析和推导应有清楚依据，但不能捏造外部出处。

无 DOI、验证失败、元数据不匹配或支持不足时，标记具体问题并暂停依赖该论据的修订，询问用户补充资料、更换来源或调整论点。必用材料没有 DOI 时同样说明冲突并询问，不自动豁免，也不将缺少 DOI 判为来源不存在。用户认可不代替 DOI 验证或事实核实。

沿用已有核实记录，实际抽查或补核缺失项；未检查到的条目保持“未检查”，不能凭部分抽查声称全部文献通过。新增论据或实质改写论点后重新检查对应关系。

## 五、偏倚与逻辑谬误

保留以下检查，依据当前内容判断是否适用：

| 问题 | 检查要点 |
|---|---|
| 确认偏倚 | 是否只强调支持观点的资料，忽略会改变判断的反例 |
| 选择偏倚 | 所选案例、样本或来源能否代表声称的范围 |
| 发表偏倚 | 综合研究结果时是否只纳入阳性或显著结果；一般作业不因此自动要求系统综述 |
| P-hacking | 涉及实际统计分析时，是否反复尝试直至显著或选择性报告 |
| 事后归因 | 是否仅因为事件 B 在 A 之后发生，就认定 A 导致 B |
| 相关与因果混淆 | 证据是否只说明关联，正文却声称因果关系 |
| 草率泛化 | 是否从个例或有限样本推出普遍结论 |
| 挑选数据 | 是否只选有利数值，忽略不同口径或不利结果 |

指出问题时给出具体位置和推理缺口，不能仅贴上偏倚标签。

## 六、实验与统计的条件审查

仅当作业涉及实验、数据分析，或题目明确要求时检查相应事项：

- 方法是否适合问题，步骤、数据来源及必要参数是否说明清楚。
- 统计假设、效应量、p 值、置信区间和多重比较处理是否按分析需要正确报告。
- 样本量、对照、重复及混杂因素的处理是否足以支持当前结论。
- 涉及系统比较时，比较条件是否公平；只有作业要求或具体结论确需验证时才检查消融等设计。
- 数据、计算、代码和图表是否可复核，实际结果与推测是否区分。

功效分析、额外实验或高级报告要求不作为所有本科作业的默认必选项。指出局限与要求新增实验要区分，不提出超出作业范围的不必要工作。

## 七、严格字数与语言检查

按[作业要求解析](../brainstorming-research/guide.md)确认的单位和计入范围统计待交付版本，分别核查总上限、明确下限、精确字数、分题限制及明确允许的容差，不自行增加 ±10%。预算、目测或旧稿计数不能代替最终实际计数。

assignment 未提供字数限制且用户未补充时先询问；口径歧义会影响是否达标时也须询问。无法取得指定计数工具的结果时说明未验证，不声称合规。

按[核心写作规范](../writing-core/guide.md)检查保留的禁用表达、推荐表达、信息完整性、自然语序、段落组织、建议段长和排版。段长建议不优先于作业字数硬限制。直接引语和参考文献不因风格检查而篡改。AI 检测分数不能证明写作质量或代替这些检查。

## 八、审查报告与问题分级

报告应包含审查版本与范围、已核实事项、未检查或未解决事项。使用以下结构记录可操作问题；无问题项无需凑数。

| 对应要求 | 内容位置 | 具体问题及依据 | 修改建议 | 核实状态 |
|---|---|---|---|---|

核实状态区分“已检查有问题”“已检查满足”“待补充材料”“未检查”“不适用”。论据记录另保留来源存在、DOI 验证和支持关系的各自状态，不能用一个“通过”掩盖未检查项。

- **主要问题**：偏题或漏答、关键概念或推理错误、论据虚构或无法核实、DOI 未通过、结论超出证据、字数硬限制未满足，以及关键 rubric 要求缺失。
- **次要问题**：不改变核心作答的措辞、局部衔接、标点或排版问题。若特定格式被 rubric 明确列为关键要求，应按实际影响提升优先级。

先处理影响有效性及必答要求的主要问题，再处理表达和排版。总体结论采用“尚有主要问题”“待补充核实”“本轮已检查项目通过”等准确表述，明确适用范围，不输出期刊式接收或拒稿决定。

## 九、冲突、修订与确认

评分表与文章内容或已确认方向冲突时，列出双方具体要求和位置，解释影响，暂停并询问用户；不以审查者身份自行决定优先级。用户选择保留差异时，记录其决定及未满足的评分项。

收到修订授权后，在其范围内处理问题。实质改变已确认的主要论点、论据或结构时，展示受影响部分并重新请求确认。字数、引用或事实问题修正后复查对应项目，用户确认不能使未核实项目自动通过。

当前部分完成审查后交回部分写作模块，展示内容并等待用户确认再继续下一部分。全文检查需要改动已确认内容时，也按影响范围重新确认；不将审查完成等同于用户已经批准。

## 十、反馈语气

- 建设性：说明如何改善，而不只指出不足。
- 具体：给出实际位置、依据和可执行建议。
- 平衡：说明有根据的优点和缺点，不为显得严厉而制造问题。
- 尊重：评价内容和论证，不攻击作者或使用轻蔑语言。
- 客观：按题目、证据及评分标准判断，不凭个人偏好要求增加内容。

避免模糊批评、未经核实的指控，以及超出范围的不必要实验或重写要求。
