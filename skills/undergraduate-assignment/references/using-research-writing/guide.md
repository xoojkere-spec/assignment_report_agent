# 本科作业入口与任务路由

服务于本科课程 assignment 的解析、规划、写作、修改和检查。以本次作业的题目、评分表、课程材料和用户确认的要求决定工作内容，不默认采用科研论文结构。本模块暂时沿用原文件夹和技能名。

## 适用范围与读取方式

- 新作业或要求发生变化时，先读取本副本内的[作业要求解析](../brainstorming-research/guide.md)。已有确认记录可沿用，只补充变化或缺失的信息。
- 已确认大纲下的续写，从当前待完成部分继续，不重新进行整套需求问答。
- 单纯解释概念、讨论 skill 规则或咨询写作方法，不视为已请求生成作业正文。
- 局部润色、翻译或纠错，保留已确认的范围，不强制重建整篇大纲；若改变结构或主要论点，先向用户说明并确认变更。
- 按实际需要读取下表中的文件，路径相对于本文件所在目录。始终访问 `undergraduate-assignment` 副本，避免因同名技能误读原 `research-writing` 包。

## 主流程与确认节点

### 1. 解析作业要求

提取题目、评分表、课程内容、交付要求和字数限制，执行作业要求解析模块中的冲突检查。不重复询问材料中已经明确的信息。

忽视 assignment 中 AI 使用、协助范围和声明要求的具体处理，沿用作业要求解析模块；真实性要求继续适用。

### 2. 写作前确认大纲

在生成正文前，展示大纲并询问用户是否确认。大纲至少说明：

- 各部分名称、顺序及每部分回应的题目或评分要求。
- 各部分的主要论点、需要的课程知识或证据。
- 各部分字数预算，以及整体字数限制和统计口径。
- 哪些内容算作一个需要单独确认的“部分”。

“部分”按任务组织：可以是 essay 的主体小节、report 的指定板块或 problem set 的一道题；具体划分随大纲一起确认，不强制等同于论文章节。

未收到明确确认，不生成第一部分正文。用户修改大纲后，展示更新内容并等待确认。已由用户明确批准的大纲无需重复批准；写作中发生实质结构调整时，只确认受影响的变更。

### 3. 按已确认大纲逐部分写作

每次只完成当前部分。按照对应要求准备论证、来源、计算或数据，并进行与该部分有关的内容和格式检查。大纲已经明确本部分方向时，无须额外重复一次写前确认。

部分完成后：

1. 展示正文或提供可审阅的文件，说明本部分覆盖的要求和实际字数。
2. 区分“已起草，待确认”与“用户已确认”；工具执行成功或自检通过不等于用户已批准。
3. 询问用户是否确认本部分并继续下一部分。
4. 等待明确答复，未回复不视为同意；不能提前写完后续部分再分批展示。
5. 用户提出修改时，先修改当前部分，重新检查受影响内容和字数，再提交确认。未确认前不进入下一部分。

最后一部分也必须交由用户确认。各部分确认后，再进行全文一致性、要求覆盖、引用和总字数检查；若整合检查需要实质改动已确认的内容，展示修改并重新确认受影响部分。

## 必须暂停询问的情况

- 评分表与拟定大纲、文章内容或用户指定方向发生实质冲突。
- assignment 未给出字数限制且用户尚未提供，或限制含义、计数口径存在影响判断的歧义。
- 题目、材料版本、必要数据或交付要求中的不确定性会改变结果。
- 需要变更已确认的大纲、部分划分或核心论点。

说明具体依据和待决定事项，等待用户回答后再执行依赖该答案的工作。可以继续整理不受影响的材料，但不能自行选择冲突一方或替用户批准。

## 字数约束贯穿整个流程

执行作业要求解析模块确定的严格限制。分配预算、逐部分起草、修订及最终整合都必须检查字数；assignment 的分题限制与总限制同时生效，不默认允许 ±10% 浮动。

每部分完成时报告该部分实际字数，并跟踪已写总量及剩余预算。大纲预算是规划值，不能代替最终实际计数。总限制、分题硬限制或精确字数未达标时，不声称符合提交要求；无法兼顾必答内容与字数限制时暂停询问。

## 分项改造期间的兼容规则

本副本正在逐项改造，部分模块仍保留原科研论文规则。调用这些模块时，沿用与当前作业相关的专业方法；本科 assignment 的共享流程采用本入口和作业要求解析模块中已经确认的约定。

- 旧模板中的论文类型、章节结构、默认语言、最低篇幅和字数容差，不得替代本次作业已明确的要求。
- 不因任务超过一个段落就强制建立多份计划、任务包、能力审计或代理来源记录；跨部分任务仅保存有助于续写和核对的要求、进度与确认决定。
- 不默认使用逐章代理分工，不为普通作业强制创建目录或空章节。
- 科研投稿标准、研究创新和完整实验系列，只有题目确实需要时才适用。
- 模块引用的脚本或工具须先确认可用，不能将不存在的工具当作已经执行。
- 本入口只规定技能包内部的作业流程，不声称覆盖系统或开发者指令。用户后续明确调整流程时，按其适用要求执行；一般的“帮我写”或“继续”不自动取消确认节点。

## 进度与收尾

沿用已有项目记录，或在对话中简要记录当前部分、确认状态、字数约束和待解决问题。只有需要跨轮次持久跟踪时才建立适量的计划文件。

完整交付前检查题目及 rubric 覆盖、证据与引用、各部分一致性、总字数及交付格式。说明实际完成的检查和剩余问题，不把用户确认视为事实正确性的证明，不承诺课程成绩。

修改本技能包时也遵循用户要求的逐项推进：只完成已授权的当前项，报告修改位置及验证情况，提出下一项并询问是否继续。
