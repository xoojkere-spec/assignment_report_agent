# 本科作业部分写作

将用户已确认的大纲落实为当前部分的正文或解答。沿用原路径与技能名，写作单位改为大纲中确认的“部分”，不强制采用论文章节。

## 一、写作前检查

读取[入口规则](../using-research-writing/guide.md)、已有要求解析结果、大纲与进度。采用[流程控制](../paper-orchestration/guide.md)中的状态和确认规则。

开始新部分前确认：

- 大纲已获用户明确确认，当前部分的范围和顺序清楚。
- 当前部分要回答的问题、对应评分项、主要论点与课程知识已经明确。
- 总字数限制、分题硬限制、当前部分预算和统计口径已确定；用户明确确认无字数限制时沿用该记录。
- 前一部分已确认；若用户明确调整写作顺序，先记录调整，不能自行跳过确认。
- 必需材料可读取；不存在会影响本部分写作的未解决冲突或关键歧义。

缺失信息时返回[作业要求解析](../brainstorming-research/guide.md)处理相关问题，不重问已经明确的信息。缺少 `plan/` 或 `chapters/` 本身不是障碍，对话中明确的大纲和确认记录同样有效。

大纲已明确本部分方向时可直接开始，不重复设置写前批准。改变主要论点、结构或部分边界时，先说明影响并请用户确认。只进行局部润色或翻译时沿用已授权范围，不强制重建整篇大纲。

## 二、准备本部分的论证与依据

在写作前明确本部分的回答、推理路径及需要的证据。资料处理按实际需要读取[证据驱动写作](../evidence-driven-writing/guide.md)或[文献处理](../literature-review/guide.md)，不强制为每段建立单独文件。

### 论据核实

采用流程控制模块的两层核实：

1. 来源是否真实存在：实际查看原文、出版记录、可靠数据库、官方数据或用户提供的材料，核对对应信息。
2. 来源是否支持该论点：读取相关段落、表格或数据，核对对象、条件、数值及结论边界。

仅有题名、搜索摘要、形式正确的参考文献或可打开但信息不匹配的 DOI，不能据此声称论据已核实。仅读到摘要时，只能引用摘要实际支持的内容。直接引语需核对原文与定位信息，不能编造页码。

为具体论点保留可追溯的来源和定位信息，沿用现有核实记录，避免重复检索；新增论点、数值、引语或来源时补充核实。使用用户经历时标记依据为用户陈述，不声称已独立验证，也不虚构个人经历。

论据未能核实或不支持论点时，暂停依赖它的写作，说明缺口并询问用户是否补充材料、换用可核实来源或调整论点。可以整理不受影响的材料，但不能用猜测补成完整正文。不将“未找到”断言为“不存在”。

用户自己的分析、演算与外部事实要明确区分；解释推理并核对输入，不为原创分析捏造文献。模拟数据和示例只能按其真实性质标注，不能充当真实研究结果。

## 三、依据作业类型展开内容

以题目和已确认大纲为准，下表是内容组织指导，不是统一模板。

| 类型 | 当前部分的写作重点 |
|---|---|
| Essay | 明确观点，以证据和解释展开论证；题目要求评价时，提出评价标准，比较适用条件、局限或反方观点 |
| Report | 按指定板块回应问题，区分事实、分析、结论和建议；建议应由前文分析支持 |
| Case study | 准确提取案例事实，用课程理论分析具体情境，解释判断理由及方案权衡 |
| Reflective writing | 基于用户真实提供的经历，联系课程概念分析认识变化，并提出具体改进；第一人称事实陈述遵循写作规范，不用禁用的主观引导句代替分析 |
| Problem set | 按题展示必要假设、公式、推导、单位和答案，检查计算或边界条件，不强行改写为论文段落 |
| 编程作业 | 遵守题目给定的接口、语言和约束，给出实现与必要解释，用适当测试验证；未实际运行时如实说明 |
| 实验或数据报告 | 清楚说明方法、数据、分析过程和结果边界；不虚构实验、统计数字或已执行的操作 |

对 explain、compare、evaluate 等题目动作采用相应深度：解释需说清机制或理由；比较需使用共同维度；评价需有标准、证据和判断。不能仅复述资料而声称完成分析。

本科层次的表达应准确、可理解，并使用课程所需概念；不靠堆砌术语增加复杂度，也不以本科层次为由省略必要推理。需要学科指导时仅读取相关模块，不套用期刊投稿要求。

## 四、表达与结构

- 每段围绕清楚的问题或观点，解释证据为什么支持判断；段落之间按论证关系衔接，不机械强制固定句数或顺序。
- 引言交代具体题目、范围和回答方向；结论回应题目并收束已有论证。除非作业要求，不自动加入研究空白、创新点或未来研究。
- 只有题目、大纲或交付要求需要时才写摘要、独立文献综述或研究方法，不附加默认篇幅。
- 人称、标题、列表、表格和强调格式遵循写作规范及用户已确认的要求；正文优先连贯论证，列表仅用于写作规范允许的场景。课程模板或体裁的明确要求与语言规范冲突时，先询问用户。
- 避免无信息量的套话、重复和过度概括，执行写作规范中保留的禁用表达规则。不以 AI 检测分数或“无 AI 痕迹”作为质量证明。
- 翻译和润色保留原有含义、证据、限定条件与学生表达特点；不悄悄改变立场或增加未经核实的事实。
- 用户的修改指令、评分检查记录、字数报告和待确认事项放在正文之外，不能混入提交内容。作业明确要求的反思或过程说明仍按题意写入。

[写作规范](../writing-core/guide.md)集中规定用户选择保留的语言风格、禁用表达、段落和排版要求；本模块不自动放宽这些规则。段落长度是建议，assignment 的严格字数限制仍须遵守。

## 五、写作与修改中的字数控制

写作前查看当前预算、已写总量和剩余必答内容。写完后按确认口径实际计数，更新当前部分及总量；不要用预估字数代替实际统计。

区分规划预算和 assignment 硬限制。超出规划预算时检查整体可行性；需要实质调整已确认分配时先询问。超过总上限或分题上限、低于明确下限，或未达到精确字数要求时，先修改，不能标为符合提交要求。

压缩时优先删除重复、偏题和低价值表述，保留必答内容、证据解释、推导和结论边界。扩写时补充有用的分析，不堆砌背景或重复结论。不默认允许 ±10% 浮动。

每次修改后重新计数；无法兼顾内容要求与字数限制时暂停询问。全文尚未完成时，报告“当前累计字数”，不能称为最终总字数。最终统计方式无法使用时明确说明未验证。

## 六、提交当前部分前检查

| 检查层次 | 核查内容 |
|---|---|
| 要求检查 | 题目与评分项覆盖、课程知识、已确认大纲、语言和格式、实际字数及硬限制 |
| 内容检查 | 概念和推理准确、分析充分、计算正确、来源存在、证据支持关系、引语准确、与前文一致 |

发现 rubric 与文章实质冲突时，展示双方具体位置并暂停询问，不自行选择优先级。对自行可修正且不改变已确认方向的语言或计算错误，修正后重查。

需要用户决定的问题保持待处理状态。未核实论据不得包装为已证实事实；用户希望保留的待核实版本只能标为草稿，不能声称已具备提交条件。

## 七、展示、确认与继续

当前部分完成检查后，提供完整可审阅内容或实际文件链接，并在正文之外说明：

- 本部分名称、覆盖的题目或评分要求。
- 实际字数、适用硬限制与统计口径，必要时列当前累计字数及剩余预算。
- 论据核实范围及尚未解决的问题；没有运行的检查不能写成已通过。
- 状态为“待用户确认”。

询问：“请确认这一部分，或指出需要修改的地方；确认后是否继续下一部分？”

等待明确回答。收到修改意见后只修改当前部分或用户明确指定的相关内容，重新检查并提交确认；不能直接进入下一部分。实质改变其他已确认部分时，说明影响并重新确认受影响部分。

记录批准所对应的实际版本。用户确认不代替字数验证、来源核实或事实检查。最后一部分同样需确认，之后交回流程控制模块进行全文检查。

输出到用户指定文件或已有项目结构；无文件要求时可以在对话中展示，不强制写入 `chapters/`。保存文件与完成检查不等同于用户已经批准。
