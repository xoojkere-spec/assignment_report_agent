# 核心写作规范

本技能用于控制本科 assignment 写作质量，保留原有语言风格、句法、段落和排版规范，并补充英文表达与课程作业论证要求。

<EXTREMELY-IMPORTANT>
以下规范必须严格遵守，不得因为"效率"或"简化"而跳过。
</EXTREMELY-IMPORTANT>

## 一、去AI化语言规范

### 1.1 禁用表达

| 类型 | 禁用词/句 |
|------|-----------|
| 机械过渡词 | 首先、其次、最后、此外、另外、接下来、总之 |
| 空壳强调句 | 值得注意的是、需要指出的是、重要的是、必须强调的是、显而易见 |
| 空洞修饰词 | 非常、极其、十分、相当（无数据支撑时） |
| 主观引导句 | 我认为、我觉得、我个人看法是（作业正文禁用） |

### 1.2 推荐表达

1. 用语义衔接替代模板衔接
2. 用数据和事实替代形容词
3. 长短句交替，避免等长句连续出现
4. 用"本文""案例表明""表X显示"等客观主语，但避免连续重复同一模板
5. 保留必要的限定、承接和少量重复，使段落读起来像自然连贯的中文作业正文

### 1.3 句法与信息密度

1. 列表转段落时补足主语、谓语和连接成分
2. 一句话围绕一个主要关系展开，必要时保留条件、范围和解释，不要强行压成短句
3. 保留分析依据、条件、对象和数据，不用"很多""较大提升"等模糊表述
4. 去AI化不等于压缩。若改短后丢失数据口径、适用边界、评价对象或结论限制，应恢复必要说明

### 1.4 中文作业的自然行文原则

中文作业不追求每句话都极度精简。更自然的写法通常是先交代分析对象、资料范围或问题背景，再说明分析过程、相关现象和判断边界。句子可以略长，段落中可以有必要的承接、限定和少量重复，只要主语明确、关系清楚、读者能够顺着论证过程理解即可。

去AI化的重点是减少模板化、翻译腔、过度概括和空泛拔高，而不是删除所有修饰语。能够说明对象、时间范围、样本口径、分析条件、指标含义、适用边界和因果关系的成分应当保留。不要把段落改成机械的"背景-分析-结论-意义"句组，也不要让每句话都呈现"对象-动作-结论"的功能句。

当用户反馈"太AI""太精简""像翻译"时，先检查是否存在过度压缩、英文语序、模板化总结、解释写作过程的表达或空泛拔高。处理顺序是补回必要信息，调整为中文自然语序，再收束过强判断。不要继续简单删词。

### 1.5 常见AI化症状与处理

| 症状 | 处理方式 |
|------|----------|
| 句式像英文直译 | 改为中文常用语序，先说明对象和现象，再给判断 |
| 段落过度模板化 | 取消固定的"背景-分析-结论-意义"节奏，保留解释句和承接句 |
| 改写后信息变少 | 补回分析对象、数据范围、分析条件、指标口径和结论边界 |
| 解释写作过程的口吻 | 将"该指标反映的是""不能理解为"改成正文叙述，如"本文将...作为参照" |
| 空泛拔高 | 用具体指标、现象或限定替代"显著""关键""重要意义"等泛化词 |

## 二、输出排版规范

### 2.1 Markdown正文规范

1. **正文默认不使用加粗和斜体**
2. **段落之间必须空一行**
3. **正文段落优先连续叙述，不用项目符号堆叠观点**
4. 同一段尽量保持单一中心观点
5. 避免把一个完整观点拆成过多短段

### 2.2 允许使用列表的场景

仅以下场景可用列表：
- 计划文档（`plan/*.md`）
- 检查清单
- 参数配置
- 操作步骤

**作业正文默认不用列表。**

## 三、段落构建规则

一个标准段落包含：

1. **主题句**：本段核心结论
2. **支撑句**：依据、证据、解释
3. **收束句**：过渡或小结

**建议长度：**
- 中文正文：150-300字
- 英文正文：100-200词

## 四、列表转段落规则

### 错误写法

```
本部分的分析如下：
- 指出案例问题
- 联系课程概念
- 解释问题成因
```

### 推荐写法

```
案例中不同部门的信息记录不一致，导致交接时反复核对。
从课程中的协调成本概念来看，重复核对增加了沟通负担，也说明统一记录规则可能有助于改善交接。
```

## 五、引用与事实

<HARD-GATE>
1. 不编造文献或数据
2. 引用格式与全文统一
3. 含有结论性表述时，优先给出处或数据
</HARD-GATE>

## 六、三轮质量检查

### 第一轮：结构检查

- [ ] 是否存在正文列表化
- [ ] 段落是否围绕单一中心
- [ ] 各部分逻辑是否连续
- [ ] 是否把正文写成机械的"背景-分析-结论-意义"模板段

### 第二轮：语言检查

- [ ] 是否出现禁用过渡词
- [ ] 是否出现禁用强调句式
- [ ] 是否存在无信息量形容词堆积
- [ ] 是否出现主观化表述
- [ ] 是否存在翻译腔、英文语序或解释写作过程的表达
- [ ] 是否因过度压缩丢失分析对象、数据范围、分析条件、指标口径或结论边界
- [ ] 是否用具体数据和现象支撑"提升""有效""稳定"等判断

### 第三轮：排版检查

- [ ] 是否有无意义加粗
- [ ] 段间是否统一空一行
- [ ] 标点与中英文空格是否一致

## 七、风格自检

按上述三轮检查逐项审阅。存在可用且适配当前语言的风格检查脚本时，可用于定位禁用表达和排版问题；先确认脚本路径及功能，不能声称运行了不存在的脚本。

自动词语检查只能提供定位信息，不能证明论证正确、引用真实或“无 AI 痕迹”。逐项检查适用范围：直接引语和参考文献中的原文不因禁词而篡改，检查重点是自行撰写的正文。

## 八、执行约束

1. 按[流程控制](../paper-orchestration/guide.md)沿用已有要求、确认状态和进度记录，长任务保留必要的持久记录，不强制为语言修改另建多份文件。
2. 本模块不取消写作前确认大纲和每部分完成后的用户确认。
3. 若用户明确要求保留特定风格，以用户要求优先。
4. 本模块保留原有禁用表达和正文风格。其他模块不能以一般性的“按体裁灵活处理”为由自动取消这些规则。若 assignment 明确要求与规则冲突，例如指定反思句式、列表或模板格式，先说明冲突并询问用户如何处理。
5. 段落长度仍是建议，不是额外的硬性字数要求；不能为了达到建议段长而违反 assignment 的严格总字数或分题限制。

## 九、英文 assignment 表达补充

英文写作沿用准确、自然、信息完整的原则，但使用英文自然语序，不将中文句法逐字翻译。

- 主语和动作清楚，避免连续使用冗长名词串、堆叠从句或无意义的被动句。长短句交替，必要的解释和限定不能因简化而丢失。
- 明确指代对象，避免 this、it 或 they 指向不清。课程术语、缩写及同一概念的译名保持一致，不为追求词汇变化随意替换专业概念。
- 观点之间以实际逻辑承接，避免反复套用 Firstly / Secondly / Finally 的编号式段落，以及 It is worth noting that / It is obvious that 等空壳强调句。
- 不以 I think / I feel / In my personal opinion 代替有根据的判断。表达局限时说明依据和适用条件，不靠无依据的 very、extremely 或夸张评价增强语气。
- 根据证据强度选择判断措辞；不能把 suggests、may 或 is associated with 润色成 proves、always 或 causes，除非论据确实支持这一变化。
- 语言版本和引用格式按已确认要求执行；没有规定时保持全文一致，影响评分的歧义需先询问。
- 英文段落仍采用主题句、支撑句和收束句的组织指导，建议 100–200 词；不要为凑词数补入重复总结或空泛背景。

## 十、课程作业论证补充

保持原有段落风格，在支撑句中解释“论据为什么支持本段观点”，不能只放入引用或罗列事实。必要时说明替代解释、反例或适用边界，再将分析联系到题目。

- explain：解释概念、关系或原因；不能只换一种说法重复定义。
- compare：采用共同维度比较，说明差异意味着什么；不能将两份介绍简单并列。
- evaluate：明确判断标准，结合论据权衡，再形成有限定的结论。
- reflect：基于用户实际提供的经历解释认识变化和改进方向，不虚构经历；仍遵守禁用主观引导句的规则。第一人称事实陈述不等于“我认为”等空泛判断句；若题目明确要求使用禁用句式，按冲突规则询问。

论据必须同时核实来源存在及对具体论点的支持关系，执行[流程控制中的论据审查](../paper-orchestration/guide.md)。语言自然不能替代真实性检查，修改措辞后要确认是否改变了原论据能够支持的范围。

本文件第四节的案例是句式示例，不是已核实的真实事件；不能把示例当作作业论据直接引用。

## 十一、严格字数下的信息保留

润色前后使用已确认口径实际计数。压缩时删除重复、偏题和无信息量表述，保留论点、证据解释、分析条件与结论边界；扩写时补足推理和必要分析，不能堆砌形容词或重复段意。

原有“去AI化不等于压缩”的原则继续适用，但不得据此超出 assignment 字数限制。不默认增加容差；篇幅要求与必要内容无法兼顾时，暂停询问用户。缺少字数限制或计数口径不明确时，按[作业要求解析](../brainstorming-research/guide.md)处理。
